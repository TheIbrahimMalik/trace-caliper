# Factory Usage Log

This document records how the TraceCaliper MVP was built using **Factory.ai** as the
primary development platform — orchestrating an AI-powered multi-agent Mission to go from
a blank repository to a fully tested, documented CLI in a single sprint.

---

## Overview

TraceCaliper was built from scratch using a Factory.ai **Mission**: a structured,
multi-agent software development workflow where an **Orchestrator** decomposes a product
specification into discrete features, assigns them to specialist worker **Droids**, and
gates progress through validation milestones.

The entire codebase — Python package, Pydantic models, scoring engine, CLI, test suite,
and these documentation files — was authored by Factory.ai Droids, reviewed through the
Factory **Review** flow, assessed via a **Security Review**, and gated through a
**Readiness** check before each milestone was declared complete.

---

## Mission Structure

### Platform: factory.ai

The project was created at [factory.ai](https://factory.ai) as a new Mission. The user
provided a product specification; the Orchestrator parsed it into 14 discrete features
grouped across 4 milestones.

### Milestones

| Milestone | Description |
|---|---|
| Foundation | Package skeleton, Pydantic models, example artifacts |
| Engine | Scoring engine, failure-mode detectors, comparison + gate logic |
| CLI & Report | Typer CLI commands, Skill Delta Report renderer |
| Polish | Tests, README, docs, security hardening |

---

## Worker Droids

Each feature was executed by a **Droid** — an AI agent specialized for Python development.
Worker Droids followed the `python-worker` Skill procedure:

1. Read `library/architecture.md` and `AGENTS.md` for mission context
2. Write failing tests first (TDD / RED phase)
3. Implement the feature (GREEN phase)
4. Run `.venv/bin/pytest -q` to confirm the full suite remains green
5. Run CLI end-to-end checks and capture output
6. Commit with a descriptive message

Each Droid reported its findings in a structured handoff, including test names, commands
run, exit codes, observed output, and any discovered issues.

## Reviews Performed

### Factory Review

After each milestone, the Orchestrator invoked the Factory **Review** flow to inspect
changes. The Review surfaced:

- A missing subprocess-level test for `python -m tracecaliper --help` (added in the
  `readme-and-docs` feature per review feedback).
- A potential host-path leak in the report footer's `comparison_path` display (fixed by
  normalizing via `Path(comparison_path).name`).

These non-blocking observations were tracked in the Mission's `features.json` and
addressed by the appropriate Droid.

### Security Review

The **Security Review** Skill was applied to the completed codebase to verify:

- No secrets, API keys, or credentials in source code or example traces.
- No network calls in any module (`requests`, `httpx`, `urllib` are absent from the
  dependency tree).
- No LLM invocations or external telemetry.
- No absolute host paths embedded in generated artifacts.

The review confirmed the offline/no-network posture.  See
`docs/security-review-notes.md` for details.

### Readiness Check

Before each milestone gate, a **Readiness** report was generated by running the
`init.sh` script from a clean state and executing the full validation contract.  The
readiness check confirmed Python 3.12 availability, venv creation, package installation,
and baseline test passage before marking each milestone ready for validation.

## Key Factory.ai Features Used

| Feature | How It Was Used |
|---|---|
| **Mission** | Decomposed a 14-feature roadmap into atomic Droid tasks |
| **Droid / Worker** | Executed all coding features (Python, YAML, Markdown) |
| **Skill** | `python-worker` Skill defined the TDD procedure for all code features |
| **Orchestrator** | Coordinated milestone gates, assigned features, reviewed handoffs |
| **Review** | Post-milestone code review catching regressions and improvements |
| **Security Review** | STRIDE + OWASP scan of the completed codebase |
| **Readiness** | Dry-run validation before each milestone gate |

## Outcome

The entire TraceCaliper MVP — from blank repo to working CLI with comprehensive test
coverage — was built in a single Factory.ai Mission sprint meeting a hard Sunday deadline.
The mission produced:

- 9 Python source modules with full type hints
- 10+ pytest test files covering 139 validation assertions
- 3 working CLI commands (inspect / compare / report)
- A polished Skill Delta Report flagship artifact
- This documentation set

The project serves dual purpose: a portfolio artifact for a **Tessl Research Engineer**
application (agent harness, eval methodology) and a **Factory.ai Customer Success Manager**
case study (real usage log of Missions, Droids, Review, Security Review).

## Standalone readiness report

- Factory feature used: `/readiness-report`
- Outcome: Factory produced a repo-readiness diagnostic for TraceCaliper.
- Full report: stored in Factory app, not included in this public repo.
- Summary: see `docs/factory-readiness-report.md`.
